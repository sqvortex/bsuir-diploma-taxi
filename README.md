# Viago

Дипломный проект БГУИР: программное средство бронирования мест в межгородских
маршрутных такси по расписанию с прогнозированием свободных мест.

Стек: Python 3.12+, Django 5.2, PostgreSQL 16 (для быстрого старта можно SQLite), Bootstrap 5,
Chart.js, pandas и scikit-learn (прогноз), Docker, pytest.
План этапов: [docs/plan.md](docs/plan.md).

## Как запустить у себя

```bash
# 1. Создать виртуальное окружение и установить библиотеки
python -m venv .venv
source .venv/bin/activate          # в Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Создать базу данных (файл db.sqlite3) по моделям
python manage.py migrate

# 3. Создать администратора (спросит телефон в формате +375XXXXXXXXX и пароль)
python manage.py createsuperuser

# 4. Загрузить пример: 3 маршрута, автопарк, пользователей всех ролей, рейсы на две недели и брони
python manage.py load_demo

# 5. Создать историю перевозок за 1,5 года и обучить прогноз (около минуты)
python manage.py generate_history
python manage.py train_forecast

# 6. Запустить сайт и открыть http://127.0.0.1:8000/
python manage.py runserver
```

## Демо-пользователи

Команда `load_demo` создаёт пользователей всех ролей, пароль у всех `demo12345`:

| Телефон | Роль | Что увидит в кабинете |
|---------|------|------------------------|
| +375293333333 | пассажир | свои поездки |
| +375291111111, +375291111112, +375291111113 | водители | свои рейсы по дням и посадочная ведомость |
| +375292222222 | диспетчер | панель с рейсами дня, панель диспетчера |

Администратор создаётся командой `createsuperuser` и видит ещё и пользователей по ролям.

## Название, цвета и тёмная тема

Название сервиса задаётся одной строкой `SITE_NAME` в `config/settings.py`.
Все цвета собраны в начале файла `static/css/theme.css`: светлая тема в блоке `:root`,
тёмная в блоке `:root[data-bs-theme="dark"]`. Тема переключается кнопкой с луной и солнцем
в шапке сайта, выбор запоминается в браузере.

## Расписание

Рейсы создаются по шаблонам расписания: кнопкой «Создать рейсы» в панели диспетчера
или командой (её удобно запускать раз в сутки планировщиком):

```bash
python manage.py generate_trips --days 14
```

## Бронирование

- Бронь занимает места только на своём участке: одно место можно продать
  на Минск – Бобруйск и на Бобруйск – Гомель.
- Двойная продажа последнего места исключена: перед подсчётом мест рейс блокируется
  в базе (`SELECT ... FOR UPDATE`), код в `bookings/services.py`.
- Пассажир отменяет бронь сам не позже чем за `BOOKING_CANCEL_HOURS` часа до посадки
  (по умолчанию 2), диспетчер может отменить в любой момент до отправления.
- Водитель в день рейса отмечает пассажиров: «сел» или «не явился». Место не явившегося
  освобождается. При завершении рейса пассажиры без отметки записываются как «не явился».
- В одной брони не больше `BOOKING_MAX_SEATS` мест (по умолчанию 5). Обе настройки в `config/settings.py`.

## Прогноз свободных мест

1. `python manage.py generate_history --days 540` создаёт выполненные рейсы и брони за прошлые
   дни по шаблонам расписания. Спрос зависит от дня недели, времени, месяца и праздников,
   правила описаны в `forecast/simulation.py`. Повторный запуск не дублирует рейсы.
2. `python manage.py train_forecast --test-days 60` учит модель (градиентный бустинг
   из scikit-learn) на всех днях, кроме последних 60, проверяет её на этих 60 днях
   и сравнивает с простым средним (средняя загрузка таких же рейсов за 4 прошлые недели).
   Таблица с ошибками печатается в консоль, модель сохраняется в `var/forecast_model.joblib`.
3. Пассажир видит прогноз в поиске («к отправлению останется 3–5 места»), диспетчер на
   странице «Прогноз»: график на 14 дней, загрузку каждого рейса и советы добавить рейс,
   поставить машину побольше или поменьше, совместить полупустые рейсы.

Модель стоит переобучать раз в неделю той же командой `train_forecast`.
Пока модель не обучена, сайт работает как раньше, только без прогноза.

## PostgreSQL и Docker

Самый простой способ запустить сайт с PostgreSQL: установить
[Docker Desktop](https://www.docker.com/products/docker-desktop/) и выполнить в папке проекта:

```bash
docker compose up --build                          # сайт на http://127.0.0.1:8000/
docker compose exec web python manage.py load_demo # демо-данные
docker compose exec web python manage.py generate_history
docker compose exec web python manage.py train_forecast
docker compose exec web pytest                     # тесты на PostgreSQL
```

Без Docker можно подключиться к своему PostgreSQL: задайте переменные окружения
`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT`.
Если `POSTGRES_DB` не задана, используется SQLite (файл `db.sqlite3`).

Тест одновременной покупки последнего места (`test_last_seat_is_sold_once`)
работает только на PostgreSQL, на SQLite он пропускается.
